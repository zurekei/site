# data/ — データ形式仕様書

`ズレ計`が扱う全データの列定義・記法規約をまとめる。監査者・貢献者向けの技術文書であり、一般読者向けの文章ではない(公開範囲の位置づけは`../CLAUDE.md`の「情報公開の3段階」を参照)。

## 1. 方針

- このディレクトリ内のCSVがソースオブトゥルースである。DBは持たない。
- 出典のない数字は掲載しない。すべての数値行に一次資料へのURL(`*_source_url`列、`fertility_actual.csv`では`source_url`列)を付す。
- 実績値は後から改定されることがある(例: 国民経済計算の確報、国際収支の速報→確定)。そのため取得時点や確報/速報/概数の別を`notes`列に記録する。
- 更新は年1回の手動運用を前提とする(自動化しない)。

## 2. 用語

- **年度(fiscal_year)**: 日本の会計年度。4月開始・翌年3月終了で、開始年の西暦で表記する(例: `2024`は2024年4月〜2025年3月)。`gdp_forecast.csv`など大半のファイルはこの列を使う。
- **暦年(year)**: 1月開始・12月終了の西暦。`fertility_actual.csv`・`fertility_forecast.csv`・`births_actual.csv`・`births_forecast.csv`の`year`/`target_year`はこちらで、年度ではない。
- **当初見通し/当初予算**: 対象の年度が始まる前(経済見通しは前年12月頃の閣議了解・1月頃の閣議決定、予算は前年12月〜1月頃の閣議決定)に示された最初の予測値。年度途中の補正予算・上方/下方修正は含まない。
- **実績/決算**: 年度終了後に確定した値。指標によって呼び方が異なる: 国民経済計算(GDP)は「確報」、消費者物価・失業率は統計調査の確定値、税収・国債発行は予算に対する「決算」額。
- **速報/概数/確報**: 統計の確定段階を表す語。速報・概数は将来改定される可能性がある暫定値、確報は改定が想定されない確定値を指す。指標ごとに三段階すべてが存在するとは限らない。
- **vintage(版)**: `fertility_forecast.csv`のみで使う語。社人研「日本の将来推計人口」が公表された年(=推計の版)を指す。1つのvintageの中に、複数の`target_year`(推計対象の将来暦年)についての仮定値が並ぶ。

### gdp_forecast.csv

実質・名目GDP成長率。政府経済見通しの当初値と、国民経済計算(SNA)の確報値を並べる。

| 列 | 内容 | 単位 |
|---|---|---|
| `fiscal_year` | 年度 | - |
| `forecast_real` | 実質GDP成長率(対前年度比)の当初見通し | % |
| `forecast_nominal` | 名目GDP成長率(対前年度比)の当初見通し | % |
| `actual_real` | 実質GDP成長率の実績(確報) | % |
| `actual_nominal` | 名目GDP成長率の実績(確報) | % |
| `forecast_source_url` | 見通しの出典URL | - |
| `forecast_published_date` | 見通しの閣議了解/決定日(YYYY-MM-DD) | - |
| `actual_source_url` | 実績の出典URL。実質・名目で別々のURLを1セルに`実質:URL 名目:URL`の形式(半角スペース区切り)でまとめている | - |
| `notes` | 自由記述(§4.3参照) | - |
| `actual_basis` | 実績値が依拠する国民経済計算の基準。`2015base-ref`(FY1981〜1994の遡及参考系列)/`2020base-final`(FY1995〜2024の確報)の2値。実績が空欄の行は空欄 | - |
| `forecast_basis` | 見通しが依拠する概念。`gnp`(FY1980〜1993)/`gdp`(FY1994年度以降)の2値。FY1993以前の見通しはGNPベースで、実績(GDP)とは概念が異なる | - |

収録範囲: 1980〜2026年度(47行)。見通し値は全年度収録済みで、空欄は`forecast_nominal`のFY1988のみ(国会会議録に数値の言及が見つからず、『国の予算』昭和63年度版の現物か閣議決定文書原本が必要)。FY1998年度以降は内閣府の公表資料から、FY1980〜1997は経済企画庁長官の経済演説(国会会議録)・委員会質疑・『平成財政史』から収集しており、行ごとの取得元は`forecast_source_url`と`notes`に記録している。実績値は1981年度から収録(1980年度は接続元系列の起点にあたり成長率を算出できないため`actual_*`列が空欄。見通し列は埋まっている)。2025・2026年度は見通しのみで実績は空欄(2025年度は国民経済計算年次推計の公表待ち、2026年度は年度未終了)。

### gdp_vintages.csv

実質・名目GDP成長率を、国民経済計算の**基準**別に並べたもの。同じ年度の成長率が基準改定でどれだけ動いたかを示すためのファイルで、見通しは持たない。実質GDP・名目GDPページの背景に描く「包絡帯」(各年度の基準別の最小〜最大)の元データ(`chart.js`の`vintageCsv`)。

**1行が「ある年度・ある基準の観測」**にあたる縦持ちのファイルで、他のファイルのように1行=1年度ではない。キーは`fiscal_year`と`basis`の組。

| 列 | 内容 | 単位 |
|---|---|---|
| `fiscal_year` | 年度 | - |
| `basis` | 国民経済計算の基準。`1990base`/`1995base`/`2000base`/`2005base-ref`/`2011base-ref`/`2015base-ref`の6値 | - |
| `actual_real` | その基準における実質GDP成長率 | % |
| `actual_nominal` | その基準における名目GDP成長率 | % |
| `actual_real_source_url` | 実質の出典URL(その基準の統計表ファイル) | - |
| `actual_nominal_source_url` | 名目の出典URL(同上) | - |
| `notes` | 自由記述(§4.3参照。ただしこのファイルの`notes`はタグを付けない。下記) | - |

基準は平成2年(1990)・平成7年(1995)・平成12年(2000)・平成17年(2005)・平成23年(2011)・平成27年(2015)の6つ。`-ref`の接尾辞は遡及参考系列であること、すなわちその基準の公表当時の系列ではなく後年に遡って推計し直したものであることを示す。`basis`の値は`gdp_forecast.csv`の`actual_basis`と**同じ語彙**であり(`2015base-ref`は両ファイルに現れる同一の系列で、実際に値も一致する)、日本語・英語の呼称も`chart.js`の`T.basisLabels`という1つの辞書から引く。

収録範囲: 137行(FY1956〜2009)。基準ごとの収録期間は`1990base`がFY1956〜1998(43行)、`1995base`がFY1981〜2003(23行)、`2000base`がFY1981〜2009(29行)、`2005base-ref`・`2011base-ref`・`2015base-ref`がいずれもFY1981〜1994(各14行)。6基準すべてが揃うのはFY1981〜1994の14年度で、包絡帯が描かれるのは基準が2つ以上ある年度だけ(実測23年度)。**その基準の対象外にあたる年度は空欄ではなく行そのものが無い**(§4.2の「空欄」は行があって値が無い場合の話なので、ここには当てはまらない)。

並び順は基準ごとのまとまり(基準は上記の年代順、その中で年度の昇順)。1つの基準の数値は統計表ファイル1本からの通し転記なので、監査するときも1基準=1ファイルで突き合わせられる形にしてある。

`notes`は`/chart/gdp-real`・`/chart/gdp-nominal`の出典欄に**そのまま表示される**(`bin/build.mjs`の`vintageSourceHtml`)。§4.3の角括弧タグは転記者向けの分類なので、このファイルでは付けない。現状記入があるのは`1995base`のFY1993・FY1994の2行で、原資料(平成7年基準の統計表)の注記にある四半期分割方法の断絶をそのまま写している。

**横持ちからの移行(2026-08-04)**: それまでは`real_1990base`…`nominal_2015base_ref`の12列を1年度1行に並べた横持ちで、数値を載せているCSVの中で唯一、行ごとの出典URL列と`notes`列を持たなかった(§1の「すべての数値行に一次資料へのURLを付す」の唯一の未達)。横持ちのまま出典を足すと基準×実質/名目で12本のURL列が要るうえ、1つの基準の出典は全年度で同じ1本なので同じ文字列が数十行ぶん並ぶ。縦持ちにすると1行が値＋出典＋notesという他ファイルと同じ形に収まり、基準が増えても列とコードではなく行が増えるだけで済む(次の2020年基準は`gdp_forecast.csv`側で既に使われている)。移行時に全12ファイルを一次資料から取り直して全274セルを再検証しており、値は1つも変わっていない。

### births_forecast.csv

社人研「日本の将来推計人口」が版ごとに置いた**出生数**の推計(出生中位・死亡中位)。`fertility_forecast.csv` が合計特殊出生率(比率)を扱うのに対し、こちらは年間の出生数(人数)を扱う。データは `bin/build_births.py` が生成する(1992年版を除き原資料のExcelを直接読む)。

| 列 | 内容 | 単位 |
|---|---|---|
| `vintage_year` | 推計が公表された年(版) | - |
| `target_year` | 推計対象の暦年 | - |
| `projected_births` | 出生数の推計値(出生中位・死亡中位) | 人 |
| `forecast_basis` | 推計人口の基準。`total`=総人口(日本における外国人を含む) / `japanese`=日本人人口 | - |
| `forecast_source_url` | 出典URL | - |
| `forecast_published_date` | 公表日。日まで特定できない場合はYYYY-MM形式 | - |
| `notes` | 自由記述 | - |

収録範囲: 7つのvintage(1992, 1997, 2002, 2006, 2012, 2017, 2023年)、計340行。高位・低位は収録していない(ページが並べるのは中位だけで、収録すれば原資料からの転記が3倍になる)。

**基準(`forecast_basis`)がこのファイル固有の要点。** 社人研が出生数を載せている表(表1-8系「出生，死亡および自然増加の実数ならびに率」)は、2012年版までが**総人口ベース**(脚注に「日本における外国人を含む．」)で、2017年版・2023年版はこれに加えて日本人人口ベースの表1-8(J)を公表している。実績側(`births_actual.csv`)は人口動態統計の「日本における日本人」しか完全な年次系列を取れないため、**基準が厳密に揃うのは2017年版・2023年版だけ**になる。基準差は2021年の実測で総人口 831,001人 vs 日本人 813,120人＝17,881人(出生数の約2.2%)で、各版の推計と実績のズレ(数万〜数十万人)より1桁小さい。混ぜたまま黙って並べないよう、`/births` は総人口ベースの版のラベルに「＊」を付け、注記で差の実測値を書く。語彙(`total`/`japanese`)は `bin/build.mjs` の `birthsBasisErrors()` が検査する。

**1992年版だけは原本がスキャンPDFで、数値を目視で書き写している。** 誤読を機械で検出できるようにするため、`bin/build_births.py` は同じ表から出生数・死亡数・自然増加数の3列を書き写し、**全35年分で「出生 − 死亡 = 自然増加」が成り立つ(丸めのため±1まで許容)ことを生成時に検算する**。1桁でも読み違えればこの恒等式が崩れる。

1992年版・1997年版は原資料が1,000人単位の整数で公表されているため、`projected_births` の下3桁が0になる。

### births_actual.csv

出生数の実績(厚生労働省「人口動態統計」)。**日本における日本人**についての数値。

| 列 | 内容 | 単位 |
|---|---|---|
| `year` | 暦年 | - |
| `actual_births` | 出生数の実績 | 人 |
| `source_url` | 出典URL | - |
| `notes` | 自由記述(§4.3参照) | - |

収録範囲: 1980〜2025年(46行)。1980〜2024年は確定数、2025年は月報年計(概数)の値で、確定数(例年9月公表)で改定される見込みであることを`notes`に記録している。`notes`は出典が変わる行にのみ記入し、それ以外は空欄。

### corrections.csv

サイトが公開した数値の訂正履歴。データそのものではなく、訂正の記録を残すための台帳。

| 列 | 内容 |
|---|---|
| `date` | 訂正を行った日(YYYY-MM-DD) |
| `target` | 訂正対象を特定できる記述(ファイル名・年度・列名など) |
| `before` | 訂正前の値 |
| `after` | 訂正後の値 |
| `reason` | 訂正理由 |
| `url` | 詳細説明への任意リンク(空欄可) |

現状0行(訂正記録なし)。`corrections.html`は`corrections.js`により、0行の場合「現時点で訂正の記録はありません」と表示する。`url`は`http(s)`以外を除外して表示される(`csv.js`の`safeUrl()`)。

### hoan_review.csv(＋ hoan_clauses/)

法律の附則に置かれた「見直し条項」(施行後◯年を目途に検討を加える等)を、施行日から算出した見直し期限順に記録する。他のファイルが「見通し vs 実績」の数値ペアを扱うのに対し、これは FORECAST=見直し条項(立法時の約束) / ACTUAL=期限到来後に検討が確認できたか、という立法版のズレを扱う。1行1法律。

対象は**直近5年(2021年以降)に成立した制定法のみ**(改正法は対象外。理由は下記)。データは `bin/build_hoan.py` が e-Gov 法令API v2 から自動生成する(手書きしない)。

| 列 | 内容 |
|---|---|
| `law_id` | e-Gov法令ID。原文サイドカー(`hoan_clauses/{law_id}.txt`)のキーも兼ねる |
| `law_title` | 法律名 |
| `law_num` | 法令番号(例: `令和三年法律第三十二号`) |
| `promulgation_date` | 公布日(YYYY-MM-DD) |
| `enforcement_date` | 当初施行日(本体施行日)。段階施行がある場合は最も遅い制定リビジョンの施行日 |
| `enforcement_note` | 注記。段階施行の法律は`段階施行`が入る |
| `review_years` | 見直し条項の「施行後◯年」の年数。期限の定めなし型は空欄 |
| `review_deadline` | 見直し期限。`enforcement_date`+`review_years`の機械算出。期限なし型は空欄 |
| `review_status` | `due`(期限到来・検討未確認) / `pending`(期限前) / `no_deadline`(期限の定めなし) / `reviewed`(検討確認済み。手動昇格) |
| `status_note` | 検討状況の説明(手動記入。現状は空欄) |
| `source_law_url` | 人間表示用の一次資料リンク(`https://laws.e-gov.go.jp/law/{law_id}`) |
| `translation_url` | 公式英訳へのリンク(`https://www.japaneselawtranslation.go.jp/en/laws/view/{id}`)。訳が無ければ空欄 |
| `translation_note` | 統制語彙。空欄 or `暫定版`(JLTの言う "Tentative translation"＝校閲前) |
| `last_checked` | 最終巡回日(YYYY-MM-DD) |

サイドカー `hoan_clauses/{law_id}.txt` は見直し条項の**原文(逐語)**を保持する。要約で置き換えない(原文＋出典が信頼性の根拠)。原文は長文でカンマ・改行を含みうるため、`csv.js`の単純パーサ(§4.4)を壊さないようCSV本体から分離している。表示側(`hoan.js`)は行展開時にこのファイルを遅延取得する。

`review_status`の設計上の要点: 検討が実施されたか否かの**自動判定はしない**(審議会・報告書・改正法など形態が多様で機械化しきれないため)。`due`までを機械的に付与し、`reviewed`への昇格は手動運用。表示でも「未確認」と「未実施」を混同しない文言にしている(検討の不在を断定しない)。

公式英訳の2列(`translation_url` / `translation_note`)は、法務省「日本法令外国語訳データベースシステム」(以下JLT)に条文の英訳があるかを**法令番号で**照会した結果。e-Gov以外の唯一の出所であり、`bin/build_hoan.py` が同じ巡回の中で毎回測り直す(訳は後から追加されるのでカバー率は上がっていく。2026-08-04時点で49法中18法=37%、うち暫定版1)。表示側は `/en/hoan` でのみリンクとして出す(JA側には出さない。JA読者にとっては `source_law_url` の e-Gov が一次資料そのもの)。照会の際に「概要情報」を検索対象から外していることが要点で、外すと訳が無い法律まで当たる — 詳細は `../CLAUDE.md` の「公式英訳の照会」。

改正法を対象外とする理由: e-Gov `/laws` は制定法しか返さず、改正法の見直し条項は改正対象の既存法の附則に`AmendLawNum`付きで畳み込まれるため、公布日フィルタでは拾えない。`build_hoan.py`は`AmendLawNum`を持たない`<SupplProvision>`(その法自身の附則)だけを抽出する。改正法対応はv2の課題。

再生成: `python3 bin/build_hoan.py`(既定で2021-01-01〜2025-12-31)。期間は`--from`/`--to`で変更できる。e-Gov と JLT の両方を巡回するので、`last_checked` は英訳の照会日でもある。※このファイルは他ファイルの「年1回手動更新」(§5)と異なり、成立法の追加に合わせた定期巡回を想定している(週次自動巡回は今後)。

## 4. 共通規約

### 4.1 列構成パターン

`bond_issuance_forecast.csv`・`cpi_forecast.csv`・`current_account_forecast.csv`・`jgb_total_issuance_forecast.csv`・`tax_revenue_forecast.csv`・`unemployment_forecast.csv`の6ファイルは、以下の共通パターンに従う。

```
fiscal_year, forecast_<指標>, actual_<指標>, forecast_source_url, actual_source_url, notes
```

このパターンに従わないファイルとその理由は以下の通り。

- `gdp_forecast.csv`: 実質・名目の2指標を1ファイルに収めているため9列になる。加えて`forecast_published_date`列を持つ点、`actual_source_url`が`forecast_published_date`の後に来る点で、上記の列順とは異なる。`actual_source_url`は実質・名目のURLを`ラベル:URL`形式で1セルにまとめており、これは同一ファイルの他5ファイルには見られない記法である。
- `gdp_vintages.csv`: 見通しを持たず、実績だけを基準別に並べたファイル。`fiscal_year`は使うが1行=1年度ではなく、`basis`との組がキーになる(1年度につき最大6行)。`forecast_*`列を持たず、出典URLは`actual_real_source_url`/`actual_nominal_source_url`の2列に分かれる(§3の該当ファイル参照)。
- `fertility_forecast.csv`: `fiscal_year`ではなく`vintage_year`/`target_year`を使う。1回の公表(vintage)が複数の対象年の仮定値をまとめて含むため、単年の見通し/実績ペアという枠組みに合わない。`actual_*`列を持たず、実績は`fertility_actual.csv`に分離されている。
- `fertility_actual.csv`・`corrections.csv`: それぞれ目的が異なる最小構成のファイルであり、上記パターンの対象外。`fertility_actual.csv`は`fiscal_year`ではなく暦年の`year`を使い、`forecast_*`列を持たない(実績のみ)。`notes`列は持つ。
- `hoan_review.csv`: 「見通し vs 実績」の数値ペアではなく、法律の見直し条項とその期限・状況を扱う台帳であり、`fiscal_year`も`forecast_*`/`actual_*`列も持たない。上記パターンの対象外(§3の該当ファイル参照)。

### 4.2 空欄と0の違い

- **空欄**: 値が存在しないのではなく、「まだ記録できていない」ことを表す。理由は主に3つ — (a)当該年度がまだ終了しておらず実績が未確定、(b)一次資料を確認できておらず見通し値が未収集、(c)原資料に該当項目の記載がない。理由は`notes`に記す。
- **`0`**: 出典において明確に0(円・%など)と確認できた場合にのみ記録する。例: `bond_issuance_forecast.csv`の1947〜1964年度は、財務省資料の脚注に「収支均衡予算のため国債発行なし」との明記があるため`0`を記録している。単に値が小さい・未確認という理由で`0`を記録してはならない。
- 描画側(`csv.js`の`toNum()`)は空文字列を`null`に変換する。`null`は「データ未収集」等として扱われ、グラフの折れ線は値が存在しない年をまたいで補間されない(隣接しない年同士を直線で結ばない)。

### 4.3 notesの記法

`notes`は複数の断片を`" / "`(半角スペース+スラッシュ+半角スペース)で連結する自由記述欄である。断片の先頭に角括弧のタグを付ける慣習があり、現状使われているタグは次の6種。

| タグ | 用途 |
|---|---|
| `[出典]` | 数値の出典・確認方法の説明 |
| `[見通し原文]` | 見通し文書の該当箇所を原文のまま引用したもの。数値自体は`forecast_*`列と重複するが、検証用に残している |
| `[見通し]` | 転記方法・注意点など、見通し値の取得に関する補足 |
| `[見通しのみ]` | 実績値がまだ存在しない(年度未終了・未確定)ことの明示 |
| `[実績]` | 実績値の出典・注記、または当該年度の背景事象の記述(例:「リーマンショック年度。」) |
| `[参考]` | 補正後予算額など、`forecast_*`/`actual_*`列に収録していない付随的な数値 |

例(`gdp_forecast.csv` 2008年度): `[実績]リーマンショック年度。 / [見通し原文]こうした結果、平成20年度の国内総生産の実質成長率は、2.0％程度（名目成長率は2.1％程度）になるなど、別添の主要経済指標のとおりと見通される。`

これらのタグは表示側で機械的に解釈される。`chart.js`の`extractEventNote()`は`" / "`で分割した断片のうち`[実績]`で始まるものだけを抽出し、グラフのイベント注記として表示する。それ以外のタグ(タイポや未知のタグを含む)は読み捨てられ画面には出ない。したがって、当該年度の出来事をグラフ上に注記したい場合は`[実績]`タグを使う必要があり、他のタグで書いても表示されない。

### 4.4 半角カンマ禁止

`csv.js`のパーサはクォート付きフィールドに対応しない単純な`split(",")`である(`csv.js` 3行目`headers = lines[0].split(",")`、5行目`cells = line.split(",")`)。そのため自由記述欄(`notes`など)に半角カンマ(`,`)を含めると、その行の列がずれて壊れる。カンマが必要な場面は読点(`、`)で代用する。全角カンマ(`，`)も紛らわしいため使わない。

行を追加・編集した際は、その行のフィールド数(カンマの個数+1)がヘッダ行のフィールド数と一致することを確認する。これは半角カンマが自由記述欄に紛れ込んでいないかの簡易的な検査になる。

### 4.5 丸め・単位換算

- 原資料が億円単位の場合は兆円に換算して記録する(`bond_issuance_forecast.csv`・`tax_revenue_forecast.csv`・`current_account_forecast.csv`)。単純換算(億円÷10000)の場合は小数4桁まで残ることがある(例: `bond_issuance_forecast.csv`の`28.6471`)。原資料自体が既に兆円単位に四捨五入して掲載している場合(`current_account_forecast.csv`)は、その旨を`notes`に「四捨五入」等と明記する。
- %表示の指標(`gdp_forecast.csv`・`cpi_forecast.csv`・`unemployment_forecast.csv`)は原資料の精度(小数1桁)をそのまま記録する。
- 出生率(`fertility_forecast.csv`・`fertility_actual.csv`)は比率であり%表記ではない。小数桁数は原資料のまま統一していない(§3の該当ファイル参照)。
- 出生数(`births_forecast.csv`・`births_actual.csv`)は人単位の整数で記録する。3桁区切りは表示側だけで付ける(§4.4のとおりCSVに半角カンマは書けない)。原資料が1,000人単位の版はその精度のまま(下3桁が0)記録し、丸めや按分はしない。
- 数値は半角ハイフン`-`を負号として使う(全角マイナス`−`や`▲`は使わない)。

## 5. 更新頻度と訂正方針

年1回の手動更新を前提とする(自動化はしない)。指標ごとの目安は以下の通り。

- **政府経済見通し(当初値)**: GDP成長率・CPI・失業率・経常収支の当初見通しは、例年12月頃の閣議了解・1月頃の閣議決定に合わせて12〜1月に追記する。
- **決算・確報**: GDP・CPI・失業率の実績、税収決算、国債発行実績は、例年7〜12月頃に確定情報を追記する。
- **人口推計**: 出生率・出生数の推計値は、社人研の公表(不定期。過去は1992, 1997, 2002, 2006, 2012, 2017, 2023年)に合わせて追記する。実績側は人口動態統計の公表に合わせ、概数が例年6月上旬、確定数が例年9月。再生成は `python3 bin/build_births.py`(`--dry-run` で書き出さずに差分だけ見られる)。

訂正方針: 一度公開した数値の誤りは、値を黙って上書きしない。訂正する場合は`data/corrections.csv`に1行追加して履歴を残し、`corrections.html`で一覧公開する。`before`/`after`列に訂正前後の値、`reason`列に訂正理由を記録する。

## 6. 検証方法

各行の`forecast_source_url`/`actual_source_url`(`fertility_actual.csv`・`births_actual.csv`では`source_url`)は一次資料への直接リンクである。監査者は該当URLを開き、その行の`fiscal_year`(または`year`・`vintage_year`+`target_year`)に対応する数値がCSVの値と一致するかを突き合わせて確認できる。

注意点:

- 財務省の一部資料(例: `sy202604f.pdf`)は同一URLのままファイル内容が更新される「時点版」の資料である。この場合`notes`に取得時点を「(ファイル名、令和X年Y月時点版)」の形式で明記しているので、URLへアクセスした時点の最新版と記録時点の版が異なる可能性がある点に留意する。
- 公式サイトのURLが後年別内容に差し替えられている場合、Wayback Machineのアーカイブ版URL(元のURLをそのまま内包する形式)を出典として用いることがある。`jgb_total_issuance_forecast.csv`の1990〜2016年度の国債発行計画(`forecast_source_url`)がこれに該当する。
- `gdp_forecast.csv`の`actual_source_url`のように1セルに複数のURLがまとめられている列は、`ラベル:URL`の形式でラベル(`実質`/`名目`)ごとに分離できる。
- `births_forecast.csv`の1992年版だけは原本がスキャンPDFで、数値を機械で読み取れない。目視の書き写しなので、`bin/build_births.py`が同じ表の出生数・死亡数・自然増加数で「出生 − 死亡 = 自然増加」を全35年分検算している(§3参照)。監査時はこの恒等式も併せて確認できる。
- `notes`の`[実績]`タグにはグラフに表示される背景事象の記述が入ることがあるが、この記述自体は評価語を含まない事実の記録である(例:「バブル期のピーク。」「消費税率引き上げ・アジア通貨危機の年度。」)。
- `hoan_review.csv`の`translation_url`は**数値の出典ではない**。その法律に公式英訳があることを示すポインタであり、CSVのどの値の裏付けでもない(その行の裏付けは`source_law_url`の側)。列名に`url`が付くため機械的な検査(`bin/build.mjs`の`sourceUrlReachErrors()`)では他の出典URLと同じ扱いで「静的HTMLから辿れるか」を見られるが、監査の際は突き合わせる数値が無い列として扱う。

このディレクトリの大半は「サイトが権利を持たないもの」でできている。政府統計の数値そのものと、`hoan_clauses/`の法令原文は、どちらもズレ計の著作物ではない。ひとつのライセンスをディレクトリ全体にかけると、持っていない権利を主張することになるため、対象を分けている。

- **CC BYの対象**: どの指標を選びどう並べたかという編集、`notes`の注記、`hoan_review.csv`の検討状況の分類、数値と一次資料URLの対応づけなど。これらはズレ計が作った部分であり、`../LICENSE-DATA`(CC BY 4.0)の対象。
- **CC BYの対象外・そもそも著作権の対象外**:
  - 各CSVの数値そのもの(`forecast_*`/`actual_*`列など)。政府等が公表した事実であり、著作権の対象ではない。
  - `hoan_clauses/*.txt`の条文原文。著作権法13条により、法律・命令等の法令はそもそも著作権の対象外と定められている。
  - 引用元の一次資料(内閣府・財務省・総務省統計局・社人研等の刊行物やPDF)そのもの。権利は各公表元にある。
